# Работа с ИИ: журнал ошибок

Проект делался вместе с Claude (Claude Code). Сюда записывается каждая ошибка ИИ,
которую мы нашли по ходу работы: что было не так, как заметили, как исправили.
Только реальные случаи из этого репозитория.

| # | Этап | Что было не так | Как заметили | Как исправили |
|---|---|---|---|---|
| 1 | Сервер | ИИ поставил тестовую библиотеку vitest версии 3 — по привычке, «как в другом проекте». В этой версии есть известные уязвимости (2 критические). | Сразу после установки `npm audit` показал 3 предупреждения. | Обновили до vitest 5, предупреждений 0. Побочный эффект: серверу теперь нужен Node 22.12+, это указано в `package.json` и README. |
| 2 | Сервер | Функцию «это та же поездка? да/нет» ИИ назвал `describeSameTrip` («описать»), хотя она ничего не описывает. | При перечитывании кода перед тестами. | Переименовали в `isSameTripData`. |
| 3 | Клиент | Запрос к серверу был без ограничения по времени: если сервер «повиснет», кнопка «Сохранить» крутилась бы бесконечно. | Ручная проверка с выключенным сервером: ответ «нет связи» пришёл только через несколько секунд, и стало видно, что ожидание ничем не ограничено. | Добавили тайм-аут 10 секунд. Повторная отправка после него безопасна: поездка уходит с тем же номером. |
| 4 | Клиент | В пустой день комиссия показывалась как «−0 ₸». | На снимке экрана пустого дня (4 октября). | Минус ставится только при комиссии больше нуля. |
| 5 | Клиент | Красная плашка «Проверьте поля поездки» оставалась после того, как поля уже исправили. | Ручная проверка формы. | Плашка сбрасывается, как только водитель меняет любое поле. |
| 6 | Проверка | ИИ решил, что кнопка «Посчитать 15%» и переключатель «Наличные» не работают. На деле снимок экрана был сделан раньше, чем интерфейс успел обновиться. | Повторный снимок через секунду показал, что всё сработало. | Код не меняли. Вывод: перед тем как чинить, перепроверять «баг» ещё раз. |
| 7 | Клиент | ИИ создал клиент на Expo SDK 54 «как в другом проекте» и написал в README, что он открывается на телефоне через Expo Go. На деле актуальная версия — SDK 57, а Expo Go из магазинов открывает только проекты на последней версии: на iPhone клиент не открылся бы вовсе. | При проверке утверждений README перед публикацией: сверили версии командой `npm view expo dist-tags`. | Обновили клиент до SDK 57 и заново проверили его в браузере. |
| 8 | Клиент | Форму добавления ИИ сделал нижней шторкой в отдельном окне (Modal), а отступ под клавиатуру настроил только для iPhone. На Android клавиатура частично закрывала поля. | Проверка на настоящем телефоне. | Форма стала слоем на весь экран в основном окне приложения, кнопки «Отмена/Сохранить» закреплены внизу, время выбирается без клавиатуры. Повторная проверка на телефоне — после этой правки. |
| 9 | Проверка | В инструкции для телефона ИИ предложил проверить обрыв связи, остановив сервер через Ctrl+C. Сервер не остановился, и проверка фактически не состоялась: поездки сохранялись без ошибок. | По журналу сервера: один и тот же процесс принимал все запросы без перерыва, а дубля в данных нет. | Проверку заменили на настоящий обрыв: выключить Wi-Fi на телефоне, нажать «Сохранить», включить и нажать ещё раз. |
| 10 | Клиент | ИИ использовал `StyleSheet.absoluteFillObject`, которого в React Native 0.86 уже нет. | Сразу при проверке типов (`tsc`). | Растяжку на весь экран записали явно: `position: absolute` и нулевые отступы. |
